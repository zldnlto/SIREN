# SIREN 앱 화면 명세서

> 기준일: 2026-05-19
> 플랫폼: Flutter (Material 3) + Riverpod + GoRouter
> 대상 기기: 산업용 태블릿 (가로/세로 모두 지원)
> 관련 결정 문서: `docs/decisions/rag_action_card_design.md`

---

## 설계 원칙

| 원칙 | 기준 |
|------|------|
| 터치 타겟 | 최소 64×64dp, 버튼 간격 ≥ 16dp |
| 가독성 | 카드 내 최소 16sp, 결함명 20sp 이상 |
| 조작 단계 | 촬영 → 결과 확인 최대 3탭 |
| 테마 | 다크 모드 우선 |
| 스타일 | 산업용 기능 중심, 소비자 앱 스타일 지양 |

---

## 화면 목록

| ID | 화면명 | 진입 조건 |
|----|--------|----------|
| S1 | 로그인 | 앱 최초 실행 / 세션 만료 |
| S2 | 홈 (촬영 진입) | 로그인 성공 |
| S3 | 검사 진행 중 | 이미지 선택 후 |
| S4 | 검사 결과 — 결함 있음 | 추론 완료 + quality_state = defect |
| S5 | 검사 결과 — 정상 | 추론 완료 + quality_state = good |
| S6 | 검사 이력 목록 | 하단 내비게이션 탭 |
| S7 | 검사 이력 상세 | S6 카드 탭 |
| S8 | 내 프로필 | 하단 내비게이션 탭 |

## 내비게이션 구조

```
로그인(S1)
  └── 홈(S2) ──────────────────────────── 하단 탭
        ├── 검사 진행 중(S3)
        │     ├── 결함 있음(S4)
        │     └── 정상(S5) → 홈(S2)
        ├── 검사 이력 목록(S6) ────────── 하단 탭
        │     └── 검사 이력 상세(S7)
        └── 내 프로필(S8) ─────────────── 하단 탭
              └── 로그인(S1)
```

## S1 — 로그인

**목적:** 사번 + 비밀번호 인증

### 컴포넌트

| 요소 | 스펙 |
|------|------|
| SIREN 로고 + 태그라인 | "LNG Tank Inspection System" |
| 사번 입력 필드 | 숫자 키보드, 마운트 시 자동 포커스 |
| 비밀번호 입력 필드 | 마스킹, 보기 토글 |
| 로그인 버튼 | 전체 너비, 최소 64dp 높이 |
| 에러 메시지 영역 | 버튼 하단, 빨간 텍스트 |

### 상태

| 상태 | UI |
|------|----|
| 기본 | 입력 폼 활성 |
| 로딩 | 로그인 버튼 → CircularProgressIndicator |
| 에러 | 에러 메시지 표시 + 셰이크 애니메이션 |

## S2 — 홈 (촬영 진입)

**목적:** 검사 이미지 입력 진입점

### 컴포넌트

| 요소 | 스펙 |
|------|------|
| 사용자 정보 헤더 | 이름 + 사번 |
| 촬영하기 버튼 (Primary CTA) | 전체 너비, 최소 80dp, 강조색 |
| 갤러리에서 선택 버튼 (Secondary CTA) | outlined, 촬영 버튼 하단 |
| 최근 검사 숏컷 카드 | 마지막 1건: 썸네일 + 결함명 + QualityBadge |

### UX

- 촬영 버튼 시각 비중 갤러리 버튼의 2배
- 숏컷 카드 탭 → S7(이력 상세)로 이동

---

## S3 — 검사 진행 중

**목적:** AI 추론 대기 상태 표시

### 상태별 UI

| 상태 | 메시지 | UI 요소 |
|------|--------|---------|
| uploading | "이미지 업로드 중..." | 선형 진행 바 (애니메이션) |
| inferencing | "AI 분석 중입니다..." | 레이더/수평 스캔 애니메이션 |
| timeout | "응답 시간이 초과되었습니다" | 재시도 버튼 (64dp) |
| network_error | "네트워크 오류" | 에러 아이콘 + 재시도 버튼 |

### UX

- uploading / inferencing 상태에서 뒤로가기 차단
- 스캔 애니메이션: 산업용 느낌 (레이더 sweep 또는 수평 스캔 라인)
- 최대 대기 가정 시간: 3초

## S4 — 검사 결과 (결함 있음)

**목적:** AI 탐지 결과 + 조치 카드 표시
**진입 조건:** `quality_state = defect`

### 레이아웃 (상→하 우선순위)

1. 이미지 뷰어 (오버레이 포함)
2. 결함 정보 행
3. QualityBadge
4. 조치 카드
5. 액션 버튼 (저장 / 보고)

### 이미지 뷰어

| 요소 | 스펙 |
|------|------|
| 베이스 이미지 | `original_url` |
| BBox 오버레이 | 기본 ON, Canvas/CustomPaint로 렌더링 |
| Grad-CAM 토글 | 우상단 버튼, 기본 OFF |
| Grad-CAM ON 시 | `gradcam_url`을 opacity 0.6으로 오버레이 |

### 결함 정보 행

| 요소 | 스펙 |
|------|------|
| display_label | 20sp 이상 Bold (예: "균열 (도장)") |
| 신뢰도 | "신뢰도 94.2%" 형식, 보조 텍스트 |

### QualityBadge

| quality_state | 배경색 | 텍스트 | 글자색 |
|---------------|--------|--------|--------|
| defect | #D32F2F (빨강) | 결함 있음 | 흰색 |

- 전체 너비 배너
- 앱바/헤더 강조색 동기화

### 조치 카드

```
┌─────────────────────────────────┐
│ [결함있음 배지]  display_label  │  ← 헤더
│ 신뢰도: 94.2%                   │
├─────────────────────────────────┤
│ 📌 원인                         │
│ {cause}                         │
├─────────────────────────────────┤
│ 🔧 조치 방법                    │
│ 1. {action_steps[0]}            │
│ 2. {action_steps[1]}            │
├─────────────────────────────────┤
│ ✅ 재검사 기준                   │
│ {reinspection_criteria}         │
├─────────────────────────────────┤
│ ⚠️ 이 안내는 참고용입니다.      │  ← 소문자 이탤릭 고정
└─────────────────────────────────┘
```

> 조치 카드 데이터 출처: `guidance` 테이블 DB 조회 (런타임 RAG 호출 없음)
> 상세: `docs/decisions/rag_action_card_design.md` §2

### 액션 버튼

**저장 버튼**

| 단계 | UI |
|------|----|
| 탭 | 확인 다이얼로그 ("검사 결과를 저장하겠습니까?") |
| 성공 | 초록 Toast "저장 완료" |

**보고 버튼 (3단계)**

| 상태 | 색상 | 레이블 | 조건 |
|------|------|--------|------|
| disabled | 회색 | "보고서 발송" | 저장 전 |
| enabled | 강조색 | "보고서 발송" | 저장 성공 후 |
| sent | 회색 | "보고 완료 ✓" | 발송 완료, 탭 불가 |

- enabled 탭 → 확인 다이얼로그 → PATCH → Toast "보고 완료"

## S5 — 검사 결과 (정상)

**목적:** 결함 없음 결과 표시
**진입 조건:** `quality_state = good`

### 레이아웃 (상→하)

1. 이미지 뷰어 (오버레이 없음, 원본만)
2. QualityBadge
3. 안내 메시지
4. 액션 버튼 (저장 / 검사 계속하기)

### QualityBadge

| quality_state | 배경색 | 텍스트 | 글자색 |
|---------------|--------|--------|--------|
| good | #388E3C (초록) | 정상 | 흰색 |

### 안내 메시지

"결함이 감지되지 않았습니다"

> 조치 카드 없음. RAG 서버 호출 없음.

### 액션 버튼

| 버튼 | 스타일 | 동작 |
|------|--------|------|
| 검사 결과 저장 | filled | 확인 다이얼로그 → POST → Toast "저장 완료" |
| 검사 계속하기 | outlined | S2(홈)으로 복귀 |

## S6 — 검사 이력 목록

**목적:** 개인 검사 기록 열람

### 컴포넌트

| 요소 | 스펙 |
|------|------|
| 페이지 헤더 | "검사 이력" |
| 날짜 필터 칩 | 오늘 / 이번 주 / 이번 달 |
| 이력 카드 목록 | 무한 스크롤 |

### 이력 카드

```
┌──────────────────────────────────┐
│ [썸네일 80×80]  display_label    │
│                 YYYY.MM.DD       │
│                 [QualityBadge]   │
│                 {domain} 공정    │
└──────────────────────────────────┘
```

- 썸네일: `original_url`, 모서리 둥글게
- QualityBadge: S4/S5와 동일 컴포넌트 재사용
- 탭 → S7(이력 상세)

### UX

- 빈 상태: "검사 이력이 없습니다" + 카메라 아이콘
- 당겨서 새로고침

---

## S7 — 검사 이력 상세

**목적:** 과거 검사 결과 재열람

S4 레이아웃 재사용, 아래 차이점 적용:

| 항목 | 변경 내용 |
|------|----------|
| 저장 버튼 | 없음 (이미 저장됨) |
| 보고 버튼 | `report_flagged` 값 기준으로 상태 결정 |
| 검사일시 행 | "검사일시: YYYY.MM.DD HH:mm" 추가 |
| Grad-CAM 토글 | S4와 동일 동작 |

**보고 버튼 상태 매핑**

| report_flagged | 버튼 상태 |
|----------------|----------|
| false | enabled ("보고서 발송") |
| true | sent ("보고 완료 ✓") |

## S8 — 내 프로필

**목적:** 계정 정보 조회 + 로그아웃

### 컴포넌트

| 요소 | 스펙 |
|------|------|
| 아바타 | 이니셜 기반 대형 원형 |
| 이름 | large |
| 사번 | 보조 텍스트 |
| 역할 배지 | "검사원" |
| 구분선 | Divider |
| 통계 행 | 총 검사 N건 \| 결함 발견 N건 \| 보고 완료 N건 |
| 로그아웃 버튼 | outlined, 하단, 중립색 (빨강 아님) |

### UX

- 로그아웃 탭 → 확인 다이얼로그 → 세션 초기화 → S1(로그인)
- 통계 행 읽기 전용
