# SIREN — Product Requirements Document

> LNG 탱크 표면 결함 AI 탐지 + RAG 기반 조치 안내 현장 보조 시스템

| 항목 | 내용 |
|------|------|
| 프로젝트 기간 | 2026-04-24 ~ 2026-05-18 (MVP) |
| 데이터 출처 | [AI Hub #Q71690](https://aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&dataSetSn=71690) |

---

## 1. 문제 정의

LNG 탱크 제조 공정의 표면 품질 검사는 현재 세 가지 구조적 문제를 가진다.

1. **육안 검사 의존** — 작업자 숙련도에 따라 결함 탐지 결과 편차 발생
2. **수동 매뉴얼 참조** — 결함 발견 후 조치 방법을 종이 매뉴얼에서 직접 찾아야 해 불필요한 시간 소요
3. **이력 미축적** — 검사 데이터가 기록되지 않아 공정 품질 트렌드 파악 불가

---

## 2. 타겟 유저

### 1차 유저 — 현장 검사원
LNG 탱크 제조 공정에서 부품을 직접 촬영하고 결함 여부를 즉시 확인해야 하는 작업자.
전문 지식 없이 태블릿 촬영 한 번으로 결함 종류와 조치 방법을 받아볼 수 있어야 한다.

### 2차 유저 — 품질 관리자 / 공정 엔지니어
공정별 불량률 추이와 결함 유형 분포를 대시보드로 모니터링하고,
반복 발생 결함 패턴을 분석해 공정 개선에 활용하는 관리자. *(MVP 제외, 확장 범위)*

---

## 3. 핵심 가치

육안 검사에 의존하던 품질 판단을 AI 비전으로 보조하여,
결함 탐지 → 위치 시각화 → 조치 안내 → 이력 저장을 하나의 흐름으로 연결한다.

작업자는 촬영 한 번으로 **무엇이 문제인지 / 어디에 있는지 / 어떻게 대응해야 하는지**를 현장에서 즉시 확인한다.

> 본 시스템은 전문 검사원의 판단을 대체하지 않는 **현장 보조 도구**이다.

## 5. 사용자 흐름

```
부품 촬영
  → 검사 요청 버튼 탭
  → AI 결함 분석 (YOLOv8 + Grad-CAM++)
  → 결함명 + confidence score 확인
  → Grad-CAM 히트맵 오버레이 확인
  → RAG 기반 조치 카드 수령
  → 심각도 배지 확인
  → 검사 로그 저장
```

## 6. 기술 전략

### 6-A. RAG 파이프라인 *(핵심 차별화)*

결함명을 키로 관련 조치 문서를 벡터 검색한 뒤 OpenAI API가 조치 카드를 생성한다.

```
결함명 입력
  → ChromaDB 벡터 검색 (Precision@3 목표)
  → 관련 SOP 청크 추출
  → OpenAI API 조치 카드 생성
      (원인 / 조치 방법 / 재검사 기준)
```

**RAG 소스**: AI Hub 구축활용가이드 + 결함별 간이 SOP 직접 작성.
실제 현장 매뉴얼 확보 전까지 조치 카드는 **"참고용 안내"** 수준으로 명시한다.

### 6-B. 풀스택 시스템 설계

Flutter 앱 → FastAPI → PostgreSQL / ChromaDB / S3로 이어지는 단일 REST API 서버.
두 클라이언트(앱·대시보드)가 동일 서버를 바라보며 검사 이력을 공유한다.

```
[Flutter 앱]
  ↓ REST API (JWT Bearer)
[FastAPI]
  ├── 이미지 수신 (S3 업로드)
  ├── YOLOv8 추론
  ├── Grad-CAM++ 시각화
  ├── RAG 파이프라인
  └── 검사 로그 저장
  ↓
[Storage]
  PostgreSQL  — 검사 이력
  ChromaDB    — RAG 벡터 DB
  AWS S3      — 원본 이미지 + Grad-CAM 결과
```

**배포**: EC2 단일 인스턴스 + Docker Compose. 메모리 압박 시 t3.large 업그레이드.

### 6-C. AI 파이프라인

| 단계 | 모델 | 역할 |
|------|------|------|
| 난이도 판별 | EfficientNet-B0 (timm) | EL2N 스코어 계산 전용, 학습 후 폐기 |
| 탐지·분류 | YOLOv8n | 결함 탐지 + 분류 (서빙) |
| 시각화 | Grad-CAM++ (torchcam) | 판단 근거 히트맵 오버레이 |

YOLOv8 출력 타입에 따라 시각화를 달리 적용한다.

| 출력 타입 | 시각화 |
|-----------|--------|
| 분류 결과 | Grad-CAM++ 히트맵 |
| bbox 탐지 | 바운딩 박스 오버레이 |
| 세그멘테이션 | 마스크 오버레이 |

### 6-D. 데이터 효율화 전략

전체 700GB 데이터를 직접 학습하지 않고 EL2N 기반으로 핵심 샘플만 추려 학습 효율을 확보한다.

```
클래스별 seed 500장 다운로드 (zip 스트리밍 추출 → 즉시 삭제)
  → EfficientNet-B0 10 epoch 학습 → EL2N 스코어 계산
  → Easy / Hard / Confident-Wrong 샘플 분리
  → Hard sample 중심 재구성 데이터셋으로 YOLOv8 학습
```

- Easy sample: 학습 우선순위 낮춤
- Hard sample: 재학습 우선 활용
- Confident-Wrong: 라벨 오류 / 혼동 클래스 후보로 검수
